# Компилятор модов — Forge 1.20.1

Изолированная Gradle-сборка для модов Minecraft 1.20.1 / Forge 47.4.10 / Java 17.
Она не меняет генератор модпака в корне репозитория.

## Сборка
Из корня репозитория: `cd "компилятор модов"`, затем `gradle build --no-daemon`
(Gradle 8.8; JDK 17; первый запуск загружает ForgeGradle и Forge).
Готовый результат: `build/libs/mca-tinkers-compat-0.1.0-alpha.jar`.

Также есть GitHub Actions workflow **Compile Forge mods**, который собирает JAR
и прикрепляет артефакт к workflow run. Зависимости MCA и TConstruct при запуске
игры должны быть установлены отдельно.

## Важно
Это **исходная заготовка для дальнейшей разработки**, не полная интеграция:
- добавлены данные MCA о подарках для перечисленных Tinkers-предметов;
- НЕ реализованы выбор экипировки, AI инструментов, рыбалка, поддержка
  всех будущих предметов TConstruct или специальные действия инструментов.
- Все эти функции требуют патчей исходной логики MCA и игрового тестирования.

Не считайте успешно собранный JAR подтверждением совместимости.

## Диагностика несовместимости (добавлено)

Встроена экспериментальная система диагностики без сетевой отправки файлов.
Для команд требуются права оператора (уровень 2).

1. `/mcatinkersdiag start` — включить запись взаимодействий с жителями MCA, если игрок держит предмет Tinkers; очищает предыдущий буфер.
2. Попробовать подарить жителю меч, молот или удочку Tinkers.
3. `/mcatinkersdiag scan` — проверить руки и броню жителей MCA в радиусе 32 блоков.
4. `/mcatinkersdiag stop` — прекратить запись; `/mcatinkersdiag status` — посмотреть статус.
5. `/mcatinkersdiag export` — сохранить JSON в `logs/mcatinkers/diagnostics-YYYYMMDD-HHMMSS.json` в каталоге игры/сервера.

Максимум 1000 событий в памяти; старые записи удаляются при переполнении.
В журнал `logs/latest.log` также пишутся диагностические записи.
В JSON фиксируются IDs предметов/типов NPC, класс NPC, тип события, измерение,
повреждение предмета и экипировка. Координаты и UUID игроков не записываются.
Лог захватывает **попытки взаимодействия**, но не доказывает сам факт
принятия подарка, экипирования или успешной рыбалки. Обязательно приложите
`latest.log` и JSON после воспроизведения проблемы.

Диагностика — отдельный этап разработки; она ещё **не исправляет**
AI MCA и не обеспечивает использование удочек, инструментов или всех
предметов Tinkers. Готовая сборка и запуск в Minecraft пока не подтверждены.

## Патчи MCA AI: рыбалка и ближний бой

Добавлены Mixin-патчи точно для MCA Reborn 7.6.28-beta.10:
- `McaFishingRodMixin`: поиск удочки в инвентаре рыбака MCA теперь
  распознаёт `tconstruct:fishing_rod`. После выбора остаётся стандартное
  поведение MCA (переход к воде, заброс, добыча рыбы).
- `McaSwordSelectionMixin`: MCA теперь учитывает `tconstruct:sword`,
  `dagger`, `cleaver`, `battlesign` и `flint_and_brick`
  в списке доступного оружия NPC, сравнивая прибавку к урону.
- Исключена необходимость компиляции с MCA JAR: для патча используются
  методы и интерфейсы Minecraft + Mixin, а классы MCA задаются как имена.
- В JAR-манифесте указывается `MixinConfigs=mcatinkerscompat.mixins.json`.

Проверка в мире **обязательна**: успешный Gradle build не подтверждает,
что Mixin внедрился в MCA и что NPC начал рыбачить или атаковать.
Для диагностики при неудачном внедрении отправь
`logs/latest.log` и `logs/debug.log`, особенно сообщения Mixin.
